# AD&D-inspired LLM Adventure Benchmark

Прототип бенчмарка для языковых моделей в текстовом приключении: модель исследует неизвестный лабиринт, запоминает поручения, сражается и распоряжается ограниченными ресурсами. Это самостоятельные упрощённые правила в духе настольных ролевых игр, не реализация и не официальный продукт AD&D.

## Быстрый старт

Нужен Python 3.10 или новее, внешние зависимости для запуска не требуются.

```bash
python -m benchmark.runner --agent baseline --seeds 1 2 3 --output results.json
python -m benchmark.runner --scenario realms --agent baseline --seeds 1 2 3 --output results-realms.json
python -m benchmark.runner --scenario expedition --agent baseline --seeds 1 2 3 --output results-expedition.json
python -m unittest discover -s tests -v
```

Базовый агент — детерминированная эвристика, получающая только те же наблюдения, что и модель. Она нужна для проверки работоспособности среды, а не как верхняя граница качества. Результат в JSON содержит показатели и трассу отдельно для каждого сида. Если `--output` не задан, JSON печатается в stdout.

Запуск модели через совместимый с OpenAI Chat Completions API:

```bash
export OPENAI_API_KEY='ваш-ключ'
python -m benchmark.runner --agent openai --model ИМЯ_МОДЕЛИ \
  --seeds 1 2 3 --temperature 0 --output results.json
```

По умолчанию используется `https://api.openai.com/v1/chat/completions`; для другого провайдера укажите полный URL через `--api-url` или переменную `OPENAI_API_URL`. При необходимости ограничьте количество наблюдений в контексте параметром `--context-turns N`. По умолчанию передаётся полная история. Для каждого хода делается отдельный запрос к API; после игры по умолчанию выполняются дополнительные запросы с контрольными вопросами. Их можно отключить через `--no-probes`. Использование API может быть платным. Доступные настройки: `python -m benchmark.runner --help`.

## Мир и правила

По умолчанию запускается `--scenario classic`, описанный ниже. Многозонный мир выбирается через `--scenario realms`, а мир с независимыми осями сложности — через `--scenario expedition`. У сценариев разные версии правил и лимиты ходов; их результаты нельзя напрямую объединять.

### Classic

Мир — связанный лабиринт 4×4 с тремя жителями, тремя поручениями и охраняемыми предметами. Модель видит текущую комнату, доступные направления, здоровье, инвентарь, местных жителей и противников. Полная карта и состояние заданий ей не показываются. Житель сообщает предмет и место только при первом разговоре: нужно найти предмет после получения задания и вернуться к его владельцу. Все названия комнат уникальны внутри мира.

На старте у героя 18 HP, три зелья и два припаса. Атака наносит 3 урона; защита стоит 1 HP и усиливает следующую атаку до 5. Живой после атаки враг отвечает на 2 HP; столько же стоит отступление или использование зелья в бою. Зелье восстанавливает до 6 HP, отдых с припасом в начальной комнате — до 8 HP. Неверное действие тоже тратит ход. Игра заканчивается после выполнения всех поручений, гибели или достижения лимита ходов (по умолчанию 120).

Модель отвечает одним JSON-объектом: `{"type":"move","direction":"north"}` или действием `talk`, `search`, `attack`, `defend`, `potion`, `rest` в поле `type`. Вне игры модель отвечает на вопросы об истории отдельными JSON-объектами.

### Realms: открытые земли, гора и подземелье

В этом сценарии 58 локаций: открытые земли 6×6, гора 3×3, башня мага 2×2 и подземелье 3×3. У каждой области своя сетка; направления `up` и `down` соединяют области и не являются перемещениями по горизонтали. Названия, дороги, расположение персонажей и входов зависят от сида. Участник видит только текущую локацию, её область, доступные выходы и видимые события; полной карты нет.

Старейшина просит вернуть реликвию из подземелья. Чтобы снять с неё печать, надо найти мага в башне и получить оберег, а затем победить дракона и обыскать логово. Необязательное поручение травницы награждает двумя зельями; выполнить его можно до завершения основного задания, после которого игра заканчивается. Поручения и местоположения сообщаются при первом разговоре.

В бою намерение врага видно заранее. Дракон чередует огненное дыхание и удар когтями; оберег снижает урон дыхания на 2. Защита снижает ответ противника до 1 HP и усиливает следующую атаку с 3 до 5; отступление при живом противнике стоит 3 HP. Зелье восстанавливает до 6 HP, но в бою враг отвечает. Лимит по умолчанию — 300 ходов; его можно изменить через `--max-turns`.

Для запуска модели используйте тот же API-адаптер с `--scenario realms`. Эвристика `--agent baseline` для этого сценария строит карту только по наблюдениям, но написана специально под правила игры. На 1000 проверенных сидах она завершила основной квест во всех партиях; это проверка работоспособности и признак того, что уровень ещё не откалиброван на разделение сильных и слабых LLM.

### Expedition: независимые параметры сложности

`expedition` — отдельная версия сценария с пятью осями. Значения конфигурации, версия движка и версии пяти подсистем записываются в отчёт; одинаковые версия, сид, конфигурация и последовательность действий воспроизводят партию. При неизменных параметрах карты изменение класса или сложности квестов, боя и NPC не меняет геометрию мира. Случайность подсистем разделена на собственные потоки.

```bash
python -m benchmark.runner --scenario expedition --agent baseline --seeds 1 2 3 \
  --map-size 8 --map-topology winding --terrain-diversity 3 \
  --quest-difficulty hard --combat-difficulty hard --enemy-count 6 \
  --character-class mage --npc-difficulty hard --output results-expedition.json
```

- **Карта:** `--map-size` — сторона открытого мира 6, 8 или 10; `--map-topology winding|mixed|open` меняет плотность дорог; `--terrain-diversity 1|2|3` меняет описание местности. Типы местности пока не влияют на движение. Башня, гора и подземелье остаются отдельными областями.
- **Квесты:** `--quest-difficulty easy|medium|hard` задаёт 2, 3 или 4 задания и глубину зависимостей. На hard основное поручение зависит от помощи следопыту. Обязательные и побочные квесты учитываются отдельно.
- **Бой:** `--combat-difficulty easy|medium|hard` задаёт число дополнительных встреч по умолчанию; `--enemy-count` позволяет переопределить их число. Враги показывают намерения: например, щит ограничивает физический удар и, на более высоких уровнях, может ограничивать огонь. Урон и сопротивления меняются с уровнем боя даже при фиксированном числе встреч. Размещение сохраняет проход к обязательным точкам; поэтому дополнительные встречи можно обойти. Если безопасно разместить заданное количество невозможно, итоговое число отражается в `result.additional_encounters_generated`.
- **Персонаж:** `--character-class generalist|warrior|mage|scout` выбирает класс. Способность, стоимость энергии и перезарядка видны в каждом наблюдении; энергия не восстанавливается со временем или отдыхом. Способность вызывается как `{"type":"ability","ability":"ID"}`; разведка показывает только соседние локации.
- **NPC:** `--npc-difficulty easy|medium|hard` меняет распределение достоверных сведений между персонажами. Локальные темы указаны в наблюдении; `{"type":"ask","topic":"ID"}` получает ответ на одну тему. Скрытая карта и полный индекс знаний NPC модели не передаются.

Неверное действие тратит ход, и противник отвечает на него в бою — пропускать таким образом опасные фазы нельзя. Бюджет по умолчанию — 600 ходов, его следует фиксировать при сравнении моделей. Базовый агент строит карту и собирает сведения только из наблюдений; он является эвристикой, а не моделью. На 30 одинаковых проверочных сидах с классом generalist он прошёл 30/30 партий профиля easy, 30/30 medium и 20/30 hard. Три оси менялись одновременно; это результат эвристики, а не LLM, и сложность ещё требует калибровки на реальных моделях.

## Что измеряется

В отчёте разделены наблюдаемые игровые результаты и ответы на контрольные вопросы. Для `realms` отдельно указаны завершение основного квеста и прогресс побочного: победа без необязательного задания остаётся победой, хотя общая доля выполненных заданий составляет 1/2. Сводный `main_quest_success` показывает долю успешных основных квестов по сидам.

Показатели:

- выполнение квестов, посещённые комнаты, ходы, недопустимые действия, полученный урон и расход зелий;
- `quest_memory`: доля правильных ответов о ранее выданных поручениях;
- `navigation_recall`: доля правильных ответов о ранее пройденных переходах между комнатами;
- `spatial_reasoning`: доля правильных ответов об относительном направлении между двумя комнатами по маршруту из нескольких наблюдаемых переходов.

Вопросы строятся только по наблюдениям и переходам, фактически виденным модели. Эталонный ответ не передаётся вместе с вопросом. Каждый вопрос задаётся независимо от других. Если пригодных вопросов нет или агент не отвечает на них, оценка отсутствует (`null`), а не считается нулевой. Неправильный или неразобранный ответ на заданный вопрос считается ошибкой. В режиме полной истории ответы могут находиться в контексте, поэтому это проверка использования контекста, а не чистое измерение долговременной памяти; в режиме ограниченного окна предыдущие события могут отсутствовать.

Память о переходах не равнозначна пространственному рассуждению. В `realms` и `expedition` переходы `up`/`down` доступны вопросам на память маршрута, а пространственные расчёты не пересекают границы областей. Пространственные вопросы проверяют лишь ограниченный аспект ориентации; их состав зависит от маршрута модели, а не задан одинаковым набором заранее. Показатели `tactics` и `strategy` остаются `null`, пока для них не добавлены отдельные валидированные задачи. Исходы боя и доля выполненных поручений — полезные косвенные показатели, но сами по себе не изолируют соответствующие способности. Не сравнивайте модели только по одному сиду, одному итоговому числу или неполным эпизодам.

## Воспроизводимость и ограничения

Мир определяется строковым представлением сида и версией движка; SHA-256 используется как детерминированный источник случайности. Одинаковые версия, сид, лимит ходов и последовательность действий дают одинаковые наблюдения и результаты, в том числе между процессами с разным `PYTHONHASHSEED`. При разных действиях партии закономерно расходятся. Все комнаты связаны, цели достижимы по карте. Обновление версии правил может изменить миры.

Детерминизм среды не гарантирует детерминизма ответа внешнего API даже при `temperature=0`. Для честного сравнения фиксируйте набор сидов, версию движка, модель и её версию, настройки генерации, размер контекста и лимит ходов; используйте одинаковые условия и несколько повторов. Не публикуйте сиды оценочного набора заранее, если планируете сравнивать модели на скрытых сценариях. Этот прототип ещё не прошёл калибровку и не является общепринятым тестом способностей. Записанные результаты содержат полную историю партии и эталоны ответов, поэтому храните их как данные оценки. [Калибровочный запуск](docs/calibration.md) поддерживает парные варианты, восстановление после сбоев и одинаковые фиксированные задачи; [результаты пилота](docs/calibration-pilot.md) описывают ограничения и проверку сложности.

Код: `benchmark/expedition.py` — сценарий с осями сложности, `benchmark/difficulty/` — независимые подсистемы, `benchmark/engine.py` — классическая среда, `benchmark/realms.py` — многозонный мир, `benchmark/realms_baseline.py` — наблюдающий агент для него, `benchmark/runner.py` — запуск и API-адаптер, `benchmark/probes.py` — контрольные вопросы, `benchmark/scoring.py` — метрики.

## Отдельные исследовательские сценарии способностей

В дополнение к прежнему `expedition` доступны новые независимые пошаговые
эпизоды: `memory`, `navigation`, `quests`, `party` и `tactics`. Они не изменяют
старую версию игры или её оценки. Сценарии намеренно изолируют условия и пока
не являются откалиброванным рейтингом LLM.

Для ручного запуска из этой директории, с **открытым исследовательским** сидом:

```bash
python -m benchmark.vector_play --axis navigation --level medium --seed dev-example
```

После каждого наблюдения введите одно JSON-действие. Доступны уровни `easy`,
`medium`, `hard`; их смысл различается по осям. `memory` проверяет сохранение
факта через отвлекающие события, `navigation` — исследование неизвестной
карты, `quests` — последовательность зависимых действий с видимым графом.
`party` и `tactics` используют отдельное приключение с наймом и боем. В
`tactics` состав фиксирован; в `party` меняется доступная вместимость, поэтому
результат зависит и от дополнительной боевой силы, не только от выбора состава.
Текущая карта партии — фиксированный диагностический случай: разные сиды не
создают независимые миры. Не смешивайте результаты этих осей или уровней в один
балл. Подробности и локальные контроли — в документации сценариев.

[Память и ориентирование](docs/memory-navigation-episodes.md) ·
[Цепочки квестов](docs/quest-chains.md)

Для совместного приключения используйте `adventure-memory`,
`adventure-navigation` или `adventure-quests`: выбранный уровень меняет только
названную ось, остальные остаются на `easy`. В одной партии нужно запомнить
одноразовую подсказку, исследовать карту, выполнить цепочку квестов и вернуться
с реликвией. Подробности — [описание и локальные контроли](docs/adventure-vectors.md).
Этот вариант не включает партию и бой; они также доступны в расширенном приключении ниже.

Для объединённого приключения с наймом и боем:

```bash
python -m benchmark.play_adventure --memory medium --navigation medium \
  --quests medium --party on --combat hard --seed dev-example
```

`--party off --combat off` возвращает поведение объединённого приключения без
этих дополнений; подробные правила и ограничения — в [документации](docs/adventure-party.md).

### Усложнённое приключение и парная калибровка

Новая версия с разнесёнными по карте заданиями, расходуемыми предметами,
одноразовой подсказкой, спутниками и боем запускается из корня проекта:

```sh
python -m benchmark.play_radical_adventure --memory hard --navigation hard \
  --quests hard --party on --combat hard --seed dev-example
```

Значения и ограничения — в [описании сценария](docs/radical-adventure.md).
Отдельные сложные тесты [памяти и ориентирования](docs/hard-memory-navigation.md)
и [квестов](docs/quest-trial.md) позволяют диагностировать способности независимо.
Они не заменяют прохождение полноценного приключения. Для сравнения моделей
используется [парный калибратор](docs/paired-codex-calibration.md), а для полной
игры — [его отдельный адаптер](docs/paired-radical-adventure.md).

[Диагностическая шкала 0–100](docs/radical-score.md) отражает обязательный
прогресс игры. [Исследовательская шкала v0.2](docs/radical-efficiency-score.md)
дополняет прогресс эффективностью победы; доля побед и технические пропуски
всегда показываются отдельно.
[Трёхмодельный runner](docs/gradient-codex-calibration.md) сравнивает Luna, Sol и
Astra на одинаковых мирах без автоматического повтора неопределённых вызовов.

[Профиль поведения](docs/behavior-profile.md) показывает успехи, причины
остановки, ходы и доступные показатели отдельных сценариев. Текущий
[калибровочный отчёт](docs/calibration-gradient-pilot.md) не являются
статистически подтверждённым рейтингом моделей.


### Воспроизводимость и локальные профили

Этот исходный код использует корневую структуру репозитория. Код исполнителей
перенесён из исследовательского workspace, поэтому его fingerprint отличается: старые
приватные планы нельзя возобновлять этой версией. Создайте новый план; seed,
журналы и доступы в репозиторий не входят. Для Codex можно задать путь к CLI
через `ADNDBENCH_CODEX_CLI`; иначе используется `codex` из PATH или путь
ChatGPT для macOS. Приватные имена планов в `scripts/behavior_profile.py` —
пример конфигурации; на другой машине замените их своими проверенными планами.

Исходные файлы статической страницы лежат в `pages/`. `model-data.js` содержит
только очищенный срез завершённых исследований; незавершённые игровые состояния
из него исключены. Чтобы сформировать собственный срез, сначала создайте локальные
`docs/behavior-profile-results.json` и `docs/behavior-profile-holdout.json`
с помощью команд в [методике профиля](docs/behavior-profile.md), затем выполните
`python3 pages/update_dashboard_data.py`. Эти JSON-отчёты и приватные планы не
входят в репозиторий. Для просмотра локально запустите
`python3 -m http.server --directory pages 8769`.

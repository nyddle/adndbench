# AD&D-inspired LLM Adventure Benchmark

Прототип бенчмарка для языковых моделей в текстовом приключении: модель исследует неизвестный лабиринт, запоминает поручения, сражается и распоряжается ограниченными ресурсами. Это самостоятельные упрощённые правила в духе настольных ролевых игр, не реализация и не официальный продукт AD&D.

## Быстрый старт

Нужен Python 3.10 или новее, внешние зависимости для запуска не требуются.

```bash
python -m benchmark.runner --agent baseline --seeds 1 2 3 --output results.json
python -m unittest discover -s tests -v
```

Базовый агент — детерминированная эвристика, получающая только те же наблюдения, что и модель. Она нужна для проверки работоспособности среды, а не как верхняя граница качества. Результат в JSON содержит показатели и трассу отдельно для каждого сида. Если `--output` не задан, JSON печатается в stdout.

Запуск модели через совместимый с OpenAI Chat Completions API:

```bash
export OPENAI_API_KEY='ваш-ключ'
python -m benchmark.runner --agent openai --model ИМЯ_МОДЕЛИ \
  --seeds 1 2 3 --temperature 0 --output results.json
```

По умолчанию используется `https://api.openai.com/v1/chat/completions`; для другого провайдера укажите полный URL через `--api-url` или переменную `OPENAI_API_URL`. При необходимости ограничьте количество наблюдений в контексте параметром `--context-turns N`. По умолчанию передаётся полная история. Для каждого хода делается отдельный запрос к API; после игры по умолчанию выполняются дополнительные запросы с контрольными вопросами. Их можно отключить через `--no-probes`. Использование API может быть платным. Доступные настройки: `python -m benchmark.runner --help`.

## Мир и правила

Мир — связанный лабиринт 4×4 с тремя жителями, тремя поручениями и охраняемыми предметами. Модель видит текущую комнату, доступные направления, здоровье, инвентарь, местных жителей и противников. Полная карта и состояние заданий ей не показываются. Житель сообщает предмет и место только при первом разговоре: нужно найти предмет после получения задания и вернуться к его владельцу. Все названия комнат уникальны внутри мира.

На старте у героя 18 HP, три зелья и два припаса. Атака наносит 3 урона; защита стоит 1 HP и усиливает следующую атаку до 5. Живой после атаки враг отвечает на 2 HP; столько же стоит отступление или использование зелья в бою. Зелье восстанавливает до 6 HP, отдых с припасом в начальной комнате — до 8 HP. Неверное действие тоже тратит ход. Игра заканчивается после выполнения всех поручений, гибели или достижения лимита ходов (по умолчанию 120).

Модель отвечает одним JSON-объектом: `{"type":"move","direction":"north"}` или действием `talk`, `search`, `attack`, `defend`, `potion`, `rest` в поле `type`. Вне игры модель отвечает на вопросы об истории отдельными JSON-объектами.

## Что измеряется

В отчёте разделены наблюдаемые игровые результаты и ответы на контрольные вопросы:

- выполнение квестов, посещённые комнаты, ходы, недопустимые действия, полученный урон и расход зелий;
- `quest_memory`: доля правильных ответов о ранее выданных поручениях;
- `navigation_recall`: доля правильных ответов о ранее пройденных переходах между комнатами;
- `spatial_reasoning`: доля правильных ответов об относительном направлении между двумя комнатами по маршруту из нескольких наблюдаемых переходов.

Вопросы строятся только по наблюдениям и переходам, фактически виденным модели. Эталонный ответ не передаётся вместе с вопросом. Каждый вопрос задаётся независимо от других. Если пригодных вопросов нет или агент не отвечает на них, оценка отсутствует (`null`), а не считается нулевой. Неправильный или неразобранный ответ на заданный вопрос считается ошибкой. В режиме полной истории ответы могут находиться в контексте, поэтому это проверка использования контекста, а не чистое измерение долговременной памяти; в режиме ограниченного окна предыдущие события могут отсутствовать.

Память о переходах не равнозначна пространственному рассуждению. Пространственные вопросы проверяют лишь ограниченный аспект ориентации; их состав зависит от маршрута модели, а не задан одинаковым набором заранее. Показатели `tactics` и `strategy` остаются `null`, пока для них не добавлены отдельные валидированные задачи. Исходы боя и доля выполненных поручений — полезные косвенные показатели, но сами по себе не изолируют соответствующие способности. Не сравнивайте модели только по одному сиду, одному итоговому числу или неполным эпизодам.

## Воспроизводимость и ограничения

Мир определяется строковым представлением сида и версией движка; SHA-256 используется как детерминированный источник случайности. Одинаковые версия, сид, лимит ходов и последовательность действий дают одинаковые наблюдения и результаты, в том числе между процессами с разным `PYTHONHASHSEED`. При разных действиях партии закономерно расходятся. Все комнаты связаны, цели достижимы по карте. Обновление версии правил может изменить миры.

Детерминизм среды не гарантирует детерминизма ответа внешнего API даже при `temperature=0`. Для честного сравнения фиксируйте набор сидов, версию движка, модель и её версию, настройки генерации, размер контекста и лимит ходов; используйте одинаковые условия и несколько повторов. Не публикуйте сиды оценочного набора заранее, если планируете сравнивать модели на скрытых сценариях. Этот прототип ещё не прошёл калибровку и не является общепринятым тестом способностей. Записанные результаты содержат полную историю партии и эталоны ответов, поэтому храните их как данные оценки.

Код: `benchmark/engine.py` — среда, `benchmark/runner.py` — запуск и API-адаптер, `benchmark/probes.py` — контрольные вопросы, `benchmark/scoring.py` — метрики.

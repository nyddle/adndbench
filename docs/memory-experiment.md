# Эксперимент с видимой картой и заметками

`benchmark.memory_experiment` запускает две версии игрового калибратора: контрольную и с детерминированной памятью. Для парного прогона используйте один приватный план и `--mode paired`: обе версии получат одинаковые модели, миры, повторы, игровой профиль, лимит ходов и параметры генерации. В плане установите `fixed_probe_difficulty: null`: этот эксперимент измеряет игровые партии, а фиксированные задания остаются отдельной оценкой.

```sh
python -m benchmark.memory_experiment --plan /private/plan.json \
  --mode paired --output-dir /private/memory-pilot
python -m benchmark.memory_experiment --plan /private/plan.json \
  --mode paired --output-dir /private/memory-pilot --resume
python -m benchmark.memory_experiment --plan /private/plan.json \
  --mode paired --output-dir /private/memory-pilot --summary-only
```

Как и исходному калибратору, для запуска нужны `OPENAI_API_URL` и `OPENAI_API_KEY`; итоговый режим не делает API-запросов и не требует ключа. `control` и `memory` хранятся в отдельных приватных каталогах. Манифест привязывает каталог к режиму, нормализованному плану, endpoint и отпечатку реализации; checkpoint также содержит режим и новый отпечаток. Отличия плана или кода требуют нового каталога. Существующие контрольные точки исходного калибратора не используются и не изменяются. Манифест и трассы содержат приватные сиды и наблюдения, поэтому каталог результатов нужно хранить приватно и не публиковать.

Память пересчитывается перед каждым ходом из полной последовательности ранее показанных наблюдений и канонических действий, включая текущее наблюдение. Она содержит видимые локации, выходы и NPC; направленные связи записываются только когда после действия перемещения наблюдается другая локация. Сообщения после разговоров, вопросов и поисков сохраняются дословно. В `visible-map-notes-v2` повторное наблюдение той же заметки перемещает её в конец списка и обновляет номер хода, если он присутствует в наблюдении. Для вопроса дополнительно сохраняется выбранная в видимом действии тема; одинаковые сообщения для разных тем считаются разными заметками. Количество заметок ограничено 40, JSON памяти — 20 000 символов; количество опущенных записей указывается в памяти. Сохраняются только сообщения после `ask`, `talk` и `search`: например, результат разведки способностью не попадает в заметки. Старые заметки остаются историческими сообщениями и не обязательно описывают текущее состояние. Если наблюдаемые имена локаций неоднозначны, карта может объединить разные локации; обратные пути и непосещённые соединения не предполагаются. При восстановлении память восстанавливается из сохранённой трассы, как и история калибратора.

V2 отличается от исследовательской `visible-map-notes-v1` порядком повторных заметок и дополнительными полями `observed_turn` и `topic`. Это изменение входа модели: для v2 нужен отдельный каталог и новый парный прогон. Checkpoints v1 нельзя продолжать в v2, а результаты версий следует показывать раздельно. Исходную копию с реализацией v1 используйте для восстановления её незавершённых партий.

В обоих режимах схема действий и длина окна последних ходов одинаковы. В режиме памяти текущее наблюдение дополнительно содержит `visible_memory`; она увеличивает размер входа и даёт модели информацию за пределами окна. Поэтому сравнение показывает эффект всей этой внешней помощи, включая дополнительные токены и детерминированную обработку, а не изолированную способность модели к памяти. 20 000 символов не являются пределом токенов и сами по себе не гарантируют укладывание в окно конкретной модели. Повторы и контроль оценивайте на одинаковых мирах; технические ошибки исключайте из игровых поражений. При ручных раздельных запусках `--mode control` и `--mode memory` одинаковость планов должен обеспечить экспериментатор. Этот модуль предназначен для отдельных процессов: он временно подменяет фабрики калибратора и не поддерживает одновременный запуск режимов в потоках одного процесса.

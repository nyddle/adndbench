# Короткая лестница памяти: 4, 6 и 8 обменов

`short-memory-0.1.0` — независимый исследовательский сценарий для поиска
промежуточной сложности. Он не изменяет исходный `hard_memory_navigation` и
ранее созданные планы. 50% завершений для Luna — цель калибровки, не заявленное
свойство какого-либо уровня.

Шесть персонажей с шестью разными предметами. Сначала модель видит назначения,
затем два списка последовательных обменов, затем получает неизвестный ранее
целевой предмет и один раз называет его конечного владельца.

| Уровень | Обменов | Размер двух групп | Правильных ходов до исхода |
|---|---:|---:|---:|
| `s4` | 4 | 2 + 2 | 4 |
| `s6` | 6 | 3 + 3 | 4 |
| `s8` | 8 | 4 + 4 | 4 |

Группы всегда две, но граница между ними находится в разных местах. Внутри
группы модель не делает действий между обменами. Предыдущий компактный base с
12 обменами показывал группы по шесть; история и условия отбора у новых уровней
различаются, поэтому это не экспериментальное повторение того же протокола.

При одинаковом seed три уровня используют **одинаковые** начальные назначения,
целевой предмет и вложенные префиксы одной восьмисобытийной истории. Каждая
модель должна получить одинаковую историю на данном уровне; для парного
сравнения уровней можно использовать один seed и оценивать связанные исходы.
Seed должны быть новыми относительно прежних запусков и различными между dev и
holdout; после выбора уровня для оценки нужны новые закрытые миры. Один и тот же
мир на нескольких уровнях не становится тремя независимыми мирами.

Для каждого из трёх префиксов целевой предмет переместился не менее двух раз,
не участвовал в последнем обмене и находится не у первоначального владельца.
Генератор отклоняет историю, если любое из трёх условий не выполнено **хотя бы
на одном** уровне; эти фильтры систематически меняют распределение истории.
Полная история нужна в контексте до ответа, включая начальные назначения.
Игра измеряет использование переданного контекста, не долговременную память.

```python
from benchmark.short_memory import create_game, SYSTEM_PROMPT, allowed_actions, source_fingerprint

game = create_game('memory-compact', 'private-seed', 's6')
obs = game.observe()
# game.step({'type': 'move', 'direction': 'forward'})
# Ответ: {'type': 'deliver', 'person': 'житель-01'}
```

Ключи ответа, seed и объект состояния доступны только оценщику. Во внешний
API передавайте публичные наблюдения и канонические действия, не заметки
модели. Неверный выбор из доступных участников заканчивает эпизод; сетевые
ошибки, прерванные запросы и лимиты runner не являются игровыми ошибками.

## Аудит shortcut на dev-мирах

`python3 -m experiments.short_memory.audit` генерирует независимый
[описательный аудит](../experiments/short_memory/dev-audit.json) по 1000
открытых dev-миров; это не оценка LLM. Контроль, воспроизводящий все обмены,
верно определил владельца 1000/1000 раз на каждом уровне. Фиксированный ответ
«первый кандидат» сработал 165/1000, 169/1000 и 171/1000 соответственно.

Важно: конечный владелец находится в паре **предпоследнего** обмена в
715/1000 миров s4, но только 277/1000 и 275/1000 миров s6 и s8. Это не
однозначный ответ, но даёт двуместную подсказку на s4: отбор приводит к
упрощению, которое надо учитывать при интерпретации модели. По условиям отбора
участники последнего обмена и изначальный владелец никогда не являются ответом;
это ещё один известный shortcut. Отсутствие других shortcut не доказано.

В том же наборе ответ не изменился при добавлении обменов s4→s6 в 723/1000
случаях и s6→s8 в 725/1000. Поэтому вложенные уровни связаны и не дают
независимых ответов; изменения не всегда затрагивают целевой предмет.

`python3 -m unittest tests.test_short_memory -v` независимо пересчитывает
владельца, проверяет вложенные префиксы, фильтры, число групп, одноразовый ответ,
replay и стабильность `PYTHONHASHSEED`.

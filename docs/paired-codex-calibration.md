# Парная исследовательская калибровка через Codex

`scripts/paired_codex_calibration.py` ведёт отдельный план для одной оси и
уровня. Сравнивает `gpt-6-luna` и `gpt-6.2-astra`, обе с `reasoning_effort=low`,
одинаковой инструкцией, историей, ограничениями и сидом. Сценарии:

- `--adapter hard_memory_navigation --axis memory` — последовательные обмены;
- `--adapter hard_memory_navigation --axis memory-compact` — те же упорядоченные
  обмены группами по шесть за ход; самостоятельный протокол, не смешивать с
  предыдущим;
- `--adapter hard_memory_navigation --axis navigation` — найти реликвию и
  вернуться через неизвестную карту;
- `--adapter quest_trial --axis quests` — многошаговый план с ресурсами.

Уровни памяти и навигации: `base`, `hard`, `extreme`, квестов: `medium`, `hard`,
`extreme`. Разные уровни создают разные миры: одинаковые seed связывают модели
внутри одного условия, но не гарантируют одинаковость мира между уровнями.

Пример из корня workspace (все лимиты относятся к **одному split**):

```sh
python3 scripts/paired_codex_calibration.py init dev-memory \
  --adapter hard_memory_navigation --axis memory-compact --level hard \
  --dev-worlds 1 --holdout-worlds 3 --max-actions 12 --context-turns 12 \
  --max-calls 30 --max-input-tokens 800000
python3 scripts/paired_codex_calibration.py run dev-memory --split dev
python3 scripts/paired_codex_calibration.py status dev-memory
# После завершения dev-пары и выбора этого протокола, без изменения кода:
python3 scripts/paired_codex_calibration.py seal dev-memory
python3 scripts/paired_codex_calibration.py run dev-memory --split holdout
```

`init`, `status`, `seal` не выполняют модельных запросов. До `seal` holdout
недоступен, после `seal` dev закрыт; завершённая dev-пара обязательна. Код,
подсказка, модель, параметры, версии CLI и отпечаток транзитивных локальных
зависимостей фиксируются в плане; изменение этих данных блокирует продолжение.
Случайные сиды dev и holdout не пересекаются и хранятся в приватном файле.
Уровни для holdout должны быть выбраны до его запуска. Нельзя проверять holdout,
подбирать по нему сложность, а затем выдавать тот же набор за независимую оценку.

Моделям передаются только правила и наблюдения, предыдущие канонические действия
и текущие публичные формы действий; сырой текст и произвольные заметки не
попадают в следующий ход. `context_turns` включает текущее наблюдение. Для памяти
план отклоняется, если окно или ограничение ходов гарантированно скроют исходные
назначения или не дадут завершить задачу. Контекстная история — проверка работы
с доступной историей, не измерение долговременной памяти за её пределами.

Проверка использует новую ephemeral-сессию Codex на каждый ход и анализирует
события инструментария. Использование инструментов означает техническое
исключение и остановку. Запрет проверяется по событиям, а не полностью закрытым
песочником: это **не противодействующая утечкам изоляция**. Codex добавляет
свои системные инструкции, поэтому этот протокол не равен Chat Completions API.

Перед каждым вызовом атомарно сохраняется `inflight`; после таймаута, сбоя CLI,
неясного результата или использования инструментов записи не повторяются
автоматически. Технический сбой и усечённый по лимиту пилот не считаются игровым
поражением. У модели есть лимит ходов игры; отдельно `max-actions` задаёт предел
исследования и может остановить ещё не завершённую игру. Отчёт показывает все
запланированные игры, терминальные исходы, неполные пары и использование, не
подставляя нули для отсутствующих результатов. Все совершённые ходы переигрываются
со сверкой наблюдений. `state.json` и `plan.json` находятся в приватном каталоге
`~/.local/share/adndbench/paired-codex-calibrations/<name>`; их не публикуют.

Лимиты `max-calls` и `max-input-tokens` — раздельно на каждый split. Первый
ограничивает число попыток, второй проверяет сумму usage **между вызовами** и
может быть превышен одним запросом; лимит времени на один запуск и таймаут одного
вызова тоже могут остановить серию. Цена неизвестна при авторизации ChatGPT;
это не жёсткий денежный лимит или точный счёт. `status` сообщает агрегаты и не
печатает скрытые сиды. Автоматические повторы и выборочно повторённые ответы
не выполняются. Для устойчивых выводов нужно больше независимых миров и
фиксирование условий до holdout; пилот на одном мире — только разведка.

Тесты без модельных запросов:
`python3 -m unittest scripts.test_paired_codex_calibration -v`.

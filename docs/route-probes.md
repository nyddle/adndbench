# Экспериментальные маршрутные пробы (route probes)

`benchmark/route_probes.py` — отдельное семейство контрольных вопросов,
построенных только из наблюдений и успешных перемещений модели. Модуль не
подключён к `benchmark/runner.py` и `benchmark/scoring.py`: как и fixed probes
v3, для оценки нужны отдельный runner, приватный план и новые закрытые сиды.
Показатель `route_planning` не смешивать с `spatial_reasoning` из `probes.py`.

## Мотивация

Существующие пространственные вопросы проверяют сумму векторов по недавнему
пути и зависят от маршрута модели; в пилоте 18 из 24 ответов пришлись на
«восток». Маршрутные пробы проверяют другое: **планирование кратчайшего пути
по собственной карте модели**. Без внутренней модели графа на вопрос ответить
нельзя: компасное направление цели не помогает при петлях.

## Построение

Из трассы берутся только успешные перемещения (направление из списка выходов,
комната в следующем наблюдении изменилась). Обратное ребро добавляется, только
если противоположный выход был виден в наблюдении комнаты назначения: проба не
использует ничего, чего модель не могла видеть, и не предполагает скрытой
геометрии. Переходы `up`/`down` участвуют наравне с компасными, поэтому пробы
могут пересекать границы зон `realms`/`expedition`.

Для каждой стартовой комнаты в порядке первого посещения строится BFS по
виденному графу с подсчётом числа кратчайших путей. Вопрос задаётся о паре
комнат на расстоянии не меньше `min_distance` (по умолчанию 4) и только если
кратчайший путь **единствен**; эталон — первое направление этого пути.
Вопросов не больше `max_probes` (по умолчанию 3), и на каждую стартовую
комнату приходится не больше одного вопроса: иначе пробы одной партии
коррелированы и часто делят первый выход. Стартовые комнаты с числом виденных
выходов меньше `min_exits` (по умолчанию 1) пропускаются. `public_probe`
удаляет эталон, `check_answer` нормализует регистр и кавычки.

## Ограничения

- Число и состав вопросов зависят от маршрута модели; при сравнении моделей
  сообщайте количество заданных вопросов, а не только долю верных. Если
  подходящих пар нет, оценка отсутствует (`null`), а не равна нулю.
- Предполагается двусторонность перемещений, видимая в наблюдениях; для
  будущих миров с односторонними дверями обратные рёбра просто не добавятся,
  и пробы останутся корректными, но более редкими.
- С `min_exits=1` (по умолчанию) у большинства стартовых комнат два известных
  выхода, и случайное угадывание даёт около 50%: проба слабая. Для оценки
  используйте `min_exits=3`. Замеры на трассах baseline-агента (публичные
  dev-сиды, `experiments/shortcut_audit.py`, не результаты моделей): при
  `min_exits=3` ожидаемая случайная точность 31–33%, эвристика «первый выход
  из списка» — 33–39% (на уровне случайной), «направление последнего
  перемещения» — 14–23%; число проб на classic снижается с 597 до 482 на 200
  сидов. Компасная эвристика по наблюдениям не вычисляется и не замерялась;
  низкая точность перечисленных эвристик не исключает других shortcut.
- Единственность кратчайшего пути — искусственное ограничение выборки; оно не
  репрезентирует случайные карты.

Тесты `tests/test_route_probes.py` независимо пересчитывают BFS, проверяют
фильтр единственности, `min_distance`, лимит вопросов, правило видимого
обратного ребра, переходы `up`/`down`, изоляцию эталона и воспроизводимость
между процессами.

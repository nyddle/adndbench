# Калибровка на LLM

Калибратор запускает партии по одинаковым сидам для каждой модели и варианта, сохраняет каждый ход и отдельно измеряет ответы на фиксированные задания. Результаты хранятся локально; фактические скрытые сиды и результаты нельзя помещать в репозиторий. Python 3.10+, внешние пакеты не нужны.

## План

Создайте приватный JSON-файл вне репозитория, например `/tmp/adnd-plan.json`. Пример структуры ниже содержит **плейсхолдеры**, а не набор для финальной оценки. Для отложенной оценки используйте новые случайные секретные сиды, которые не использовались при разработке; выбирайте их до запуска, одинаково для всех моделей и профилей. Названия моделей зависят от провайдера.

```json
{
  "models": ["MODEL_A", "MODEL_B"],
  "seeds": ["REPLACE_PRIVATE_SEED_1", "REPLACE_PRIVATE_SEED_2"],
  "repeats": 1,
  "max_turns": 200,
  "temperature": 0,
  "context_turns": 20,
  "max_tokens": 256,
  "timeout": 90,
  "base_config": {"enemy_count": 2},
  "variants": [
    {"name": "control", "changes": {}},
    {"name": "more_difficult_combat", "changes": {"combat_difficulty": "hard"}},
    {"name": "more_enemies", "changes": {"enemy_count": 4}},
    {"name": "hard_quests", "changes": {"quest_difficulty": "hard"}},
    {"name": "larger_map", "changes": {"map_size": 8}},
    {"name": "hard_npc", "changes": {"npc_difficulty": "hard"}},
    {"name": "warrior", "changes": {"character_class": "warrior"}}
  ],
  "fixed_probe_difficulty": "medium"
}
```

Один `control` без изменений обязателен; каждый другой вариант отличается от него ровно одним параметром. Для сравнения сложности боёв требуется фиксировать `enemy_count`, так как иначе профиль сложности меняет и количество противников. Изменение размера или топологии меняет весь мир, поэтому совпадение сидов не гарантирует идентичности локаций. Выбирайте оси и уровни заранее и проверяйте допустимые значения в текущем движке. Выше `max_turns` — ограничение партии, а не критерий сложности модели. `context_turns: null` оставляет всю историю; число ограничивает последние ходы. Температура и настройки едины для моделей; совместимость параметров с выбранным API надо проверить.

## Запуск и восстановление

Передайте ключ только через `OPENAI_API_KEY`, а URL совместимого chat-completions API — через `OPENAI_API_URL` либо `--api-url`. Для удалённого адреса требуется HTTPS; адрес не должен содержать учётные данные, параметры запроса или фрагмент. Отправка идёт на указанный URL целиком. Например:

```sh
chmod 600 /tmp/adnd-plan.json
python -m benchmark.calibration --plan /tmp/adnd-plan.json --output-dir results/calibration
python -m benchmark.calibration --plan /tmp/adnd-plan.json --output-dir results/calibration --resume
python -m benchmark.calibration --plan /tmp/adnd-plan.json --output-dir results/calibration --summary-only
```

Каталог должен быть доступен только владельцу. Файлы партий и заданий создаются с правами 0600, подкаталоги — 0700. Ключ, текст ошибок HTTP и заголовки в записи не сохраняются; seed, приватное состояние и ключ ответа fixed probe в API не отправляются. Трассы содержат наблюдения и исходные ответы модели: относитесь к ним и к плану как к приватным данным. Состояние контрольной точки атомарно записывается после каждого хода. `--resume` переигрывает сохранённые действия и сверяет наблюдения, продолжая с последнего записанного хода. Если ответ пришёл, но процесс завершился до записи, повторный запрос может тарифицироваться второй раз. Завершённые партии повторно не отправляются. Идентификатор записи включает версию кода, протокол, модель, endpoint, конфигурацию и seed: изменение кода или параметров создаёт новые записи и не продолжает старые. `--summary-only` не требует ключа и не делает запросов.

Оцените объём заранее: максимум `models × variants × seeds × repeats × max_turns` запросов на партии, плюс `models × seeds × repeats × 10` запросов на фиксированные задания, если они включены. Раннее завершение уменьшает первое число. Параметр `fixed_probe_difficulty` можно установить в `null`, чтобы отключить fixed probes.

## Как читать результаты

`summary.json` и вывод CLI содержат число завершённых партий, побед, смертей и завершений по лимиту; исключённые технические ошибки и незавершённые партии считаются отдельно и не являются поражениями. Числа действий, посещённых комнат и побочных квестов суммированы **только по завершённым партиям**; знаменатели тоже приведены. Для сравнения каждого варианта с контролем и каждой пары моделей указано, сколько пар с тем же seed и номером повтора имеют два валидных результата, сколько пар отсутствует и в какую сторону изменились исходы. Эти выборки могут быть смещены, если ошибки происходят не случайно. При малом числе сидов нельзя уверенно ранжировать модели; повторы одного seed не заменяют независимые миры. Температура 0 не гарантирует детерминизм провайдера.

Fixed probes используют 10 отдельных запросов на seed: восемь про пространственные маршруты и два про квесты. Повороты внутри одного seed коррелированы, поэтому количество вопросов не равно числу независимых миров; интервалы по вопросам не рассчитываются. Quest-задания показывают историю целиком и измеряют её использование в текущем контексте, а не долговременную память. Тест не измеряет в отдельности тактику или стратегию, и игровые исходы сами по себе не доказывают пространственные способности.

Протокол ходов специально требует точную схему JSON: дополнительные поля делают ход невалидным, а в историю возвращается только каноническое действие, чтобы модель не записывала произвольные заметки в собственный ответ. Невалидный ответ засчитывается как игровой невалидный ход; сбой API — как технический сбой. Этот протокол отличается от обычного runner и указан в метаданных; не смешивайте результаты разных протоколов. Ограничение окна, настройки модели, версия движка и текст инструкций влияют на сопоставимость.

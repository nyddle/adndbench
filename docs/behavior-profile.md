# Профиль поведения моделей

`scripts/behavior_profile.py` воспроизводит проверенные журналы исследовательских
партий и строит локальный отчёт по каждой модели и каждому условию отдельно:
завершено / запланировано, победы / завершено, причины окончания, средние ходы
и некорректные действия на завершённых партиях. У полной игры показываются
экспериментальный score и его компоненты. Подробные показатели каждой партии
показывают прогресс квеста, посещение комнат, спутников и бой, если доступны.

```sh
python3 scripts/behavior_profile.py --split dev \
  --markdown docs/behavior-profile-results.md \
  --json docs/behavior-profile-results.json
```

Запуск не вызывает моделей и не изменяет планы. Это снимок на момент запуска:
незавершённые партии могут продолжаться и потребуют повторного экспорта. Статусы
`ready`, `inflight`, `action_limit` и технические ошибки учитываются отдельно и
не являются проигрышами; наблюдения для них — частичные. Незапущенные модели
отмечаются отсутствующим значением. Балл начисляется только завершённой игре;
компонент неначавшегося боя имеет статус `not_attempted` и не характеризует
боевые способности. Сценарии разных версий и настроек не объединяются в одну
оценку. Числа ходов и ошибок в таблице усредняются только по завершённым
партиям, в деталях приведён статус каждого отдельного прохождения.

Отчёт раскрывает только заранее выбранные агрегаты и метрики, а не сиды,
подсказки или журнал действий. На `holdout` Sol не запускалась в рамках
расширений dev: берутся исходные парные планы, и Sol помечается как не
запускавшаяся. Незавершённые планы с нарушенным fingerprint не включаются:
в Markdown есть список недоступных условий, в JSON — причина. Сравнение
пилотов описательное, небольшие выборки не подтверждают устойчивый рейтинг.
Не публикуйте данные holdout до фиксации настройки.

Для дев-диагностик партии и тактики включены два **отдельных фиксированных
случая**, а не независимые выборки: `party-case` и `tactics-three`. Успех
выбора состава означает, что оракул BFS нашёл победную стратегию для состава;
это не победа, исполненная моделью. В тактическом случае модель сама выбирает
действия до исхода боя. Показатели сценариев не суммируются; для фиксированного
случая доля успехов и доля побед в JSON равны `null`, а в таблице приведён
конкретный исход. Для боя показываются HP героя, урон, лечение и потраченные
заряды, для выбора состава — выбранная роль. Оба сценария доступны только в dev.

Для проверочной выборки короткой памяти `--split holdout` использует отдельный
план `short-memory-4-fresh-holdout`, созданный из dev-плана `short-memory-4`.
Исследовательские dev-партии не добавляются к его holdout-знаменателю; исходная
отложенная выборка `short-memory-4` тоже не смешивается с новой. В JSON и деталях
Markdown указывается имя плана, выборка и источник форка; JSON сохраняет также
различающиеся технические бюджеты. Для создания проверочного отчёта после
завершения партий:

```sh
python3 scripts/behavior_profile.py --split holdout \
  --markdown docs/behavior-profile-holdout.md \
  --json docs/behavior-profile-holdout.json
```

Проверка: `python3 -m unittest scripts.test_behavior_profile -q` из корня проекта.

# Исследовательский сценарий партии и тактики

`party-adventure-0.1.1` — самостоятельная, воспроизводимая игра; она не меняет `expedition-0.1.0` и её результаты. Это упрощённые собственные правила в духе ролевых игр, не реализация правил AD&D. Карта, расположение кандидатов и встречи пока заданы вручную; аргумент `seed` сохраняется ради совместимости интерфейса, но **не меняет мир**. Разные seed не создают независимые миры и не подходят для оценки разброса.

## Игровой сценарий

Игрок начинает в убежище и должен найти реликвию в логове и вернуться домой. Он видит только текущую локацию и выходы. В нескольких комнатах встречаются кандидаты: защитник (`warden`), лекарь (`medic`) и маг (`mage`). Найм стоит 1 золото, по умолчанию есть 2 золота и два места. Нанять можно только присутствующего персонажа; снаряжение героя, здоровье и заряды спутников остаются в объекте партии между боями. До выбора состава наблюдение содержит разведданные о составе охраны логова и правила способностей. Чтобы не смешивать выбор и действия, `Game(fixed_party=('medic','mage'))` создаёт именно такую группу и запрещает найм; `fixed_party=None` оставляет его игроку.

В бою за раунд действует один живой член партии: обычный удар; ограниченная способность защитника уменьшить получаемый целью урон и усилить следующий удар; ограниченное лечение лекаря; игнорирующий броню удар мага. Враги объявляют цели и урон заранее. Все выжившие враги отвечают в указанном порядке; убитый противник не отвечает, мёртвая цель пропускается. Смерть героя завершает игру, павших спутников нельзя поднять лечением. Невалидное действие расходует раунд, враги отвечают. Отступления в этом прототипе нет. Победа достигается уничтожением всех противников; лимит боя и игры различаются. Все точные правила видны в `observe()`.

```python
from benchmark.party_adventure import Game, SYSTEM_PROMPT

game = Game(combat_difficulty='medium', fixed_party=None)
observation = game.observe()
observation = game.step({'type': 'move', 'direction': 'north'})
# На локации кандидата: {'type':'recruit','candidate':'mage'}
# В бою: {'type':'blast','actor':'mage','target':'raider'}
result = game.result()  # терминальный исход после завершения
```

Старый CLI не изменён; отдельный `benchmark.vector_play` поддерживает этот сценарий через оси `party` и `tactics`. Модельный адаптер должен сохранять версию, формат действия и ходы для воспроизведения. В `benchmark.party_combat` также доступны `Party.recruit`, `Party.snapshot`/`from_snapshot`, `Battle.observe`/`step` и список допустимых действий. Сценарий сам определяет фактически присутствующих в локации кандидатов; список присутствующих для прямого вызова `recruit` обязан формировать вызывающий движок.

## Раздельная локальная проверка

Скрипт `scripts/party_tactics_calibration.py` в корне workspace запускает проверку без сетевых запросов и записывает агрегаты в `party-tactics-calibration.json`. На каждую конфигурацию — **одна** вручную заданная встреча и две детерминированные стратегии: только удар героем (`strike_only`) и простая стратегия, которая использует доступные роли (`roles`). Ограниченный BFS перебирает допустимые действия того же движка и отдельно перепроверяет найденную последовательность; это проверка решаемости в этой реализации, не независимый аудит корректности движка. Результат `unknown` при исчерпании лимита состояний не означает нерешаемость.

**Тактика:** состав зафиксирован (лекарь и маг), меняется только число идентичных противников: у каждого 5 HP, 2 урона, 0 брони и цель — герой.

| Врагов | Только удар: исход / раунды / HP героя | С ролями: исход / раунды / HP | Кратчайшая победа по BFS |
|---:|---|---|---:|
| 1 | победа / 2 / 10 | победа / 1 / 12 | 1 |
| 2 | победа / 4 / 4 | победа / 2 / 10 | 2 |
| 3 | поражение / 3 / 0 | победа / 5 / 6 | 4 |

Стратегия с ролями тратит соответственно 1, 2 и 3 заряда; простая стратегия — 0. Различия показывают поведение именно этих двух политик, а не устанавливают сложность для LLM.

**Состав:** одна ячейка союзника и один фиксированный бронированный противник (12 HP, броня 2, урон 3). Только ударом ни одна из трёх групп не побеждает. Стратегия с ролями выигрывает с магом за 4 раунда и с 3 HP, с лекарем и защитником проигрывает. BFS находит решение только с магом. Это проверка, что состав в конкретной ситуации имеет значение, а не сбалансированное доказательство пользы всех классов: один этот случай заведомо благоприятен магу. Для будущей оценки нужны разнообразные заранее подготовленные встречи, где полезны разные роли, одинаковые данные разведки, больше разных миров и новые закрытые примеры.

Игра содержит три профиля столкновения для функциональной проверки, но `easy/medium/hard` одновременно меняют статистики и число врагов. Они **не** являются чистым однофакторным сравнением; для него используйте приведённые выше отдельные встречи. Пока нет калибровки на LLM: исходы моделей, реальная стоимость и обобщаемость не установлены.

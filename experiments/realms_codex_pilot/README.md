# Exploratory realms Codex-agent pilot

These are Codex-agent sessions, not OpenAI Chat Completions runner evaluations. Each fresh agent was asked to choose each action from its observations, calling a local bridge once per move. They were instructed not to inspect files or hidden state; this is not enforced by a security boundary and their tool histories were not independently audited, so it is an exploratory pilot rather than a controlled evaluation. Model system instructions and sampling settings differ from the API runner and were not controlled.

Both `gpt-6-luna` (`luna6`) and `gpt-5.6-luna` (`luna56`) used engine `realms-0.1.0`, common public seeds 1–3, a 300-turn budget, and the same player rules and instruction template. These seeds are not a held-out evaluation set. All six episodes ended in victory without operator interventions. The optional herbalist quest was not completed in any episode.

| Seed | GPT-6-Luna | GPT-5.6-Luna |
|---:|---:|---:|
| 1 | 121 turns, 1 invalid | 120 turns, 0 invalid |
| 2 | 123 turns, 0 invalid | 56 turns, 0 invalid |
| 3 | 107 turns, 0 invalid | 111 turns, 0 invalid |

After each game, questions generated by `build_probes(..., scenario='realms')` were asked **in one batch**, unlike the standard runner, with the full agent history available. All 43 responses were correct. One model received eight questions on seed 2, the other runs seven; the questions depend on each observed trajectory, so the counts and contents are not a fixed comparable test set. Only game actions and subsequent observations are recorded, not the models' full tool transcripts or reasoning.

Each `.jsonl` contains the initial observation followed by one JSON action and the resulting observation per line. `_answers.json` files contain the model's answers. Replay actions and recompute the generated question scores with:

```bash
PYTHONPATH=. python experiments/realms_codex_pilot/evaluate.py
```

These six runs establish that both tested agents passed these scenarios in this execution setup. They do not establish the performance of any model in general or guarantee that the environment separates frontier and smaller models. Results may vary on different seeds, prompts, context policies, model settings, and repeated runs.
